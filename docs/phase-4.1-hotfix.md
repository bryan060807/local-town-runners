## Changes

- One atomic additive migration: `docs/sql/phase-4.1-upgrade.sql`. Existing jobs opt out of automatic dispatch; new jobs opt in. Existing `status` values remain compatible with Phase 4; generated `job_status` exposes pending/processing/sent/failed/retrying. `sent` means provider acceptance, not delivery.
- Queue claims serialize under a database row lock; leases expire after two minutes. Claims refuse jobs with a provider receipt. Attempts, first provider send boundary, frozen request body, acceptance, and delivery events are persistent. Retry requests use the original stable provider idempotency key and an identical canonically serialized body, including after PostgreSQL JSONB reorders object keys.
- Resend API rejects configuration/validation problems into blocked status; temporary failures back off with at most five automatic attempts. An uncertain send older than 23 hours is blocked for provider reconciliation because Resend's deduplication expires at 24 hours. Explicit auth/validation/rate-limit rejections clear the uncertain send boundary; they cannot have accepted this message. A successful consent survives PDF or notification failure.
- Awaited submission processing remains server-side. The trusted worker `/api/internal/notifications` independently resumes up to five new eligible jobs, including pending PDFs. `vercel.json` schedules it once daily at 12:00 UTC, compatible with Hobby scheduling. Retries can wait up to a day; do not describe these as immediate retries. For faster automatic recovery, use a trusted external scheduler with the bearer secret or a Vercel plan supporting a more frequent cron schedule.
- Administrator-only **Resend Notification** bypasses retry backoff for an explicitly selected job, still respecting leases, existing receipts and uncertain-send reconciliation. No bulk historical retry. Failed queue/PDF states are visible in the admin UI with attempts, last attempt and provider state. Existing generic PDF retry also checks these protections.
- Emails include business name, applicant name, original submission time, ID and application status, with an authenticated admin review/download link. No PDF attachment, public Storage URL, private contacts, signature or long-lived signed URL is included. The actual administrator recipient must be configured as `aibrymusic@gmail.com`.
- `/api/webhooks/resend` verifies Svix HMAC signatures over the raw body, rejects timestamps outside five minutes and bounds the request to 64 KiB. Stored events are deduplicated; delayed/out-of-order acceptance events cannot downgrade delivery/bounce/rejection. Early events arriving before the send receipt are reconciled when the provider ID is saved. Provider delivery means delivery to the recipient's mail server, not confirmed inbox placement.
- Future PDFs use labeled vendor/runner information and readable product blocks, dollar currency, optional-field fallbacks, wrapped long values and a signature adjacent to identity/consent/time. Original 12 legal section headings and bodies are retained. Section headings avoid orphaning at a page boundary.
- Historical formatting uses **Create readable presentation copy** and **Download private presentation copy**. A separately labeled `readable-v1` document and immutable registry retain the original signed PDF unchanged. Downloads remain admin-only and signed for 60 seconds; original authorized downloads remain available. Presentation copies do not replace consent evidence.
- RLS/server admin guards remain enforced. Demo/applicant identities cannot send or create/download admin presentation copies. Local wrappers clear remote email, webhook and cron credentials. Payment logic is unchanged.
