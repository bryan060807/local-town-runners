Security review covers Auth getUser validation, Origin checks, strict schemas, RLS/column grants, role provisioning, inventory locking, block/suspension gates, private address lifetime, coarsened public coordinates, uploads and financial idempotency. No credentials or exact operational addresses are recorded here.

Public approximate: vendor public_lon/public_lat, runner public_lon/public_lat, runner trip destination vendor. Private operational: vendor_private pickup address/coordinates and order_private customer delivery address. Precise runner GPS is never persisted; browser geolocation is coarsened before local map display and never submitted. AI tools contain only public data plus the authenticated customer’s own order-state map.

Live checks: HTTPS domain responds, Supabase public REST reads succeed but catalog is empty, Sandbox OAuth succeeds. No hosted role accounts or buyer credentials were assumed. Local role/database tests and browser checks are distinct from hosted verification; simulator delivery is not proof of a successful capture.

Additional HIGH finding: current configured AI_MODEL failed with HTTP 404/model_not_found; model listing confirms it is unavailable to this key. `gpt-4.1-mini` is accessible, and an actual provider tool-call test with that model passed, returning a validated catalog listing. Production settings must be corrected; this audit did not change external Vercel configuration.

Local environment finding: Node --env-file preserves existing process variables, so earlier local seed/test scripts could accidentally select a hosted endpoint. The local wrapper now forcibly selects generated loopback credentials and removes provider/payment credentials. The initial audit seed attempt failed authentication/fetch; no hosted demo data is claimed created. All subsequent seed/reset verification targeted the dedicated local backend.
