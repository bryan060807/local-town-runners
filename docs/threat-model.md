# Threat model

| Threat                                    | Boundary/control                                                                                                 | Remaining limitation                                                                            |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Customer changes roles or financial state | Membership grants withheld; RLS; service-only payment RPC                                                        | Service credential compromise has broad power; rotate and restrict operational access           |
| Cross-user order access                   | Order RLS checks participant ownership; every action validates actor                                             | Browser/API live tests still needed against configured Supabase                                 |
| Public GPS/home address leakage           | Coarsened coordinates enforced by trigger; separate private tables                                               | Public coarse presence remains potentially sensitive; opt-in visibility and expiry are required |
| Customer address disclosure               | Customer and active assigned runner only; no catalog/AI access                                                   | Assigned runner can retain what they have legitimately seen; enforce operational policy         |
| Forged or duplicate payment               | PayPal API verification, canonical capture checks, internal custom ID, unique identifiers, locked idempotent RPC | Sandbox end-to-end and reconciliation/refunds remain unverified/unimplemented                   |
| Prompt injection                          | AI only chooses validated search parameters; no write/authorization tools                                        | Discovery relevance can still be manipulated; user reviews choices                              |
| XSS/injection/mass assignment             | React escaping, strict schemas, parameterized Supabase calls, column grants                                      | Production CSP still allows Next inline scripts; nonce hardening recommended                    |
| CSRF                                      | Exact Origin for cookie-authenticated writes; no GET state changes                                               | Same-origin compromise remains outside this control                                             |
| Abuse                                     | Supabase Auth controls plus database minute-window action limits                                                 | Offline public demo endpoints need edge limits before public high-traffic hosting               |
| Unsafe uploads                            | Bounded raster decoding, metadata stripping, ownership checks and service-only writes                            | Hosted Storage integration remains unverified                                                   |
| Unauthorized vendor/runner transitions    | Database actor-specific state machine; assigned runner check                                                     | Road-route feasibility and manual operations remain necessary                                   |

No permanent exact location history is collected. Public runner availability expires by query, trips have expiration timestamps and address access is revoked by order state. Retention cleanup should delete expired trip/rate-limit records and purge operational addresses according to a documented retention period. Order/financial audit records need legally appropriate retention and access policy.
