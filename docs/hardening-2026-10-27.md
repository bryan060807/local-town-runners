# Application hardening — October 27, 2026

This pass reviews the current hackathon application, including discovery, account controls, vendor tools, runner coordination, private demonstrations, Sandbox payment boundaries, uploads, deployment operations and project documentation. It preserves the existing Sandbox/demo scope: no Live payment, new genuine financial transaction or real payout was authorized or performed.

## Verification

Final release results are recorded in [hardening evidence](evidence/hardening-2026-10-27.json). The browser suites use production builds; desktop and mobile flows cover discovery, persistence, role permissions, catalog editing, agreement intake, genuine-payment denial, isolated simulation and full fulfillment. New failure tests cover delayed runner/vendor requests, interrupted sign-out/recovery, quantity boundaries and explicit private-document links.

The [read-only operational audit](evidence/hardening-operations-2026-10-27.json) checks the deployed source, production environment variable names, cron registration, anonymous denial, security headers, bucket privacy and existing payment records. The three genuine Sandbox orders retain their complete prior order/ledger digest, their PAID states and exactly one genuine customer-payment entry each, totaling $44.00 USD. Presence of a variable name does not independently prove a credential's value or provider authorization.

No database migration or new application environment variable is required for these fixes. Hosted Auth email, Storage writes, new signed provider deliveries and financial capture were not retriggered as part of the code regression suite. Local Storage is absent from the reduced development backend; binary/image tests and database policy tests are distinct from a hosted Storage integration test. Earlier genuine capture, signed webhook and inbox evidence remain linked from the README.

## Remaining operational work

- **Delivery feedback:** Production currently lacks `RESEND_WEBHOOK_SECRET`. Existing notification sending has accepted-provider evidence and prior inbox confirmation. To track delivered/bounced/complained states automatically, configure the matching signed Resend webhook at `https://runners.aibrylabs.com/api/webhooks/resend`, store its secret in Production, redeploy and verify an authorized delivery event. This is an optional integration completion, not a failure of the existing send path.
- **Commercial operations:** Backup/restore drills, retention and deletion handling, alert ownership, provider capacity and rate limits, road routing and a suitable sustained-use tile service remain necessary before broader public operation. A demo workspace expires for access control; it is not automatically deleted by a retention process.
- **Payments:** The audit does not enable Live, promise immediate Sandbox settlement, establish commercial approval or convert simulated allocations into actual earnings. Genuine new payment tests still require explicit authorization and buyer approval.
- **Release governance:** The new checks run automatically; administrators can separately require successful checks before merging to main. CI does not replace review or hosted integration evidence.

## Recommended next steps

1. **Freeze the hackathon feature set.** Rehearse a three-minute story: a local need, grounded discovery, a vendor storefront, one explicitly simulated order, runner coordination, completion and honest recognition. Keep the real Sandbox proof as separate evidence. Record a clean backup video and keep the submission link, screenshots and claims consistent.
2. **Run a small usability review.** Have two or three people unfamiliar with the app complete the same journey on a phone without coaching. Measure where they hesitate, whether they understand the current role and payment source, and whether the next action is clear. Fix those observed problems before adding another major feature.
3. **Prepare a limited pilot.** Configure delivery feedback, assign monitoring ownership, rehearse restoration and document consent, retention and incident handling. Test with a small number of consenting local participants while retaining the existing payment/payout boundaries.
4. **Validate monetization later.** Establish demand and operational reliability before premium subscriptions, sponsored placement billing or real payouts. Any paid placement should be disclosed and kept separate from earned reputation.
